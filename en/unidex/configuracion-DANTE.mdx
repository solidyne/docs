The UNIDEX /A67 models incorporate a Dante/AES67 module that provides **16 mono AoIP inputs and 16 mono AoIP outputs**.

Using UNIDEX on an AoIP network requires having compatible Dante devices to input or send audio signals. These devices can be, for example:

- Dante microphone preamplifiers.
- Dante line interfaces.
- Other consoles or processors with Dante.
- Computers with **Dante Virtual Soundcard**.

Any compatible Dante interface can be connected to UNIDEX, provided it shares the network parameters, sample rate, and synchronization required by the installation.

Computers can send and receive audio directly over the AoIP network via **Dante Virtual Soundcard**, an Audinate application that turns a PC or Mac into a Dante device using the standard Ethernet port.

<Warning>
  Implementing Dante requires basic knowledge of audio over IP, IP addressing, signal routing, and digital synchronization.
</Warning>

## Dante Ethernet Port Connection

### General Considerations

- The Dante Ethernet port connects to a Gigabit switch using a network cable suitable for the installation.
- In dedicated and simple networks, Dante can operate with standard Ethernet switches. In shared or managed networks, it is recommended to use managed switches and configure QoS, IGMP, or other network functions according to Audinate's recommendations.
- Do not use Wi-Fi for Dante audio traffic.
- The typical topology is star, with Dante devices connected to a central switch. Do not use the secondary Dante port to daisy-chain devices, unless the manufacturer explicitly indicates another mode of operation.
- In installations with Dante redundancy, the Primary and Secondary networks must be separate physical networks, built on independent switches. Failover switching from one network is automatic when the devices support redundancy.
- The **Remote Control** Ethernet port on UNIDEX can share the network infrastructure if the installation design allows it. In critical installations, it is recommended to validate this decision with the network technical manager.

## Dante Network Configuration

In UNIDEX, the **Settings - AoIP** screen reports the status of the Dante/AES67 module and the network.

Device management, input channels, output channels, and Dante routings are performed from a computer connected to the network using **Dante Controller**, Audinate's software for configuring and routing audio and video on Dante networks.

Dante Controller allows you to view the Dante devices present on the network, their available channels, the clock and network status, and create connections between transmitter and receiver channels.

### Clock Synchronization and Network Role

In a Dante network, devices synchronize their clocks via PTP. One device acts as the **leader clock** for the network, and the others operate as **followers**. In earlier documentation, these roles may appear as **Master** and **Slave**.

In a typical UNIDEX installation, the console can operate as the leader clock and synchronize connected Dante peripherals on the network. In more complex installations, for example with more than one console or with a pre-existing Dante system, another device may be defined as the leader clock. In that case, UNIDEX must synchronize with the clock defined for the network.

If a leader clock is not manually defined, Dante automatically chooses one from the available devices. This configuration is performed from **Dante Controller**, not from UNIDEX.

The indications available on UNIDEX, both on the touchscreen and the web interface, are informational regarding the status of the Dante/AES67 module and the network. The parameter defined from the console is the behavior of the mixing engine's clock.

Depending on the AoIP network configuration, when UNIDEX participates in Dante synchronization, the clock reference can come from:

- The UNIDEX mixing engine, if the Dante module is configured to synchronize with an external reference provided by the equipment.
- The Dante/AES67 module itself, when working with its internal clock or synchronized to the network's leader clock.

When the network's reference clock is provided by the Dante/AES67 module, the UNIDEX mixing engine's clock can operate in internal mode or synchronize to the Dante clock, according to the configuration chosen for the installation.

The usual configuration in simple installations will be to keep the mixing engine's clock in **Internal** mode. In larger Dante networks, or when UNIDEX operates as a follower to an already defined external clock, it may be advisable to synchronize the mixing engine with the Dante clock to maintain consistency with the AoIP system.

## AES67 Compatibility

In addition to Dante devices, the UNIDEX /A67 models can exchange audio with AoIP equipment from other manufacturers and ecosystems that implement the **AES67** standard. AES67 is an interoperability standard that allows compatible Dante devices to transmit and receive RTP multicast audio streams to and from AES67 devices that do not use Dante.

A particularly relevant case in broadcasting installations is **Livewire+ AES67**, used by **Axia / Telos Alliance** consoles and AoIP systems. Livewire+ AES67 implements the AES67 standard and allows the exchange of audio streams with other compatible devices. In this way, UNIDEX can integrate with Livewire+ AES67 devices via AES67 streams, provided the equipment and network are properly configured.

<Note>
  AES67 compatibility refers to **audio transport and exchange**. Proprietary functions of each ecosystem, such as discovery, control, logic, or device management, are not necessarily interoperable via AES67.
</Note>
